# 插件包回收与中断恢复

包回收由 `PackageCollectionService` 的工作线程执行。安装索引变化、安装任务结束、会话停止和应用启动都会请求一次回收；250 ms 合并重复请求。回收保留当前版本、上一版本和更新事务的 `pendingPrevious`，不会删除插件数据或来源注册记录。

安装复制、发布、索引提交、更新确认与回滚各阶段的真实进程中断证据见 [安装与更新的进程中断恢复](TransactionRecovery.zh-CN.md)。其中还独立验证回收后 current／previous／pendingPrevious 的完整性，以及恢复锁占用时的磁盘保留与重试。

## 正在使用的包

`PackageLease` 在包库 `.leases/<uuid>/` 保存一个小 JSON 记录，并持有该记录的 `owner.lock`。记录中的摘要保护一个不可变版本；空摘要保护整个包库，用于尚未知道内容摘要的下载和 ZIP 解压阶段。锁仅按进程退出判定失效，禁止按时间强制夺取活锁。

准备目录完成后，返回的 `PreparedPackage` 持有摘要 lease，直到安装提交或更新交接结束。安装索引只保存持久化字段，不保存这个临时所有权。验证任务在读取包前取得 lease，成功后交给激活会话。RPC 工作线程也持有同一个 lease：应用仍存活时，即使 GUI 会话提前销毁，实际进程退出之前仍不能回收其代码。

新安装／更新引用必须先持有匹配包库和摘要的 lease，再原子提交索引，提交完成后才释放。启停、卸载、更新确认和失败回退只保留或减少已有摘要引用，不需要获取包库发布锁。索引自己的乐观摘要检查与写入锁继续防止多个进程覆盖彼此的修改。

运行会话在 initialize 之前给 lease 绑定实际插件进程的 PID、平台和启动时间。父应用退出后，锁虽已失效，仍存活或无法确认状态的插件继续保护其摘要；PID 复用通过启动时间区分。监听父生命周期的独立 Node worker 负责终止主线程卡死的插件进程组。详细规则和故障验证见[父应用退出与插件进程所有权](ProcessSupervision.zh-CN.md)。

## 回收顺序

1. 工作线程取得 `.store.lock`，阻止出现尚未被本轮观察到的新 lease 和包目录发布。
2. 先检查 lease：活锁对应摘要加入保留集合；活的空摘要使本轮延后。锁已失效但绑定的实际插件仍存活或状态未知时，也保留摘要。确认退出或没有运行绑定的失效记录可以移除。任何记录损坏或无法检查时停止回收并保留文件。
3. 然后读取原子保存的当前安装索引，加入所有当前、上一版与事务备份摘要。索引损坏、超预算、指向符号链接或格式不合法时不回收包和安装临时目录。
4. 在保留集合之外，仅处理应用生成的摘要目录和 `.stage-*`、`.unpack-*`、`.download-*`、`.trash-<uuid>`。摘要目录还必须包含匹配的所有权 receipt；未知目录和不安全条目留存。
5. 检查目录不包含符号链接／特殊文件、越界层级和超预算条目，原子改名为唯一 trash 目录。每轮最多退休八个包／临时目录，另外最多移除八个失效 lease。
6. 释放发布锁，再删除已退休的文件。删除期间的临时活动 lease 防止另一回收线程改名同一批 trash，正常索引提交与安装可以继续。剩余垃圾由后续批次处理。

第 2 步必须先于第 3 步：并发提交的新引用，要么仍被本轮观察到的活 lease 保护，要么 lease 已在提交完成后释放，此时后续读取的安装索引已经包含该摘要。这让回收不必持有索引写入锁，也避免清理线程使正常停用失败。

取消或进程中断发生在改名之后，可能留下 trash；下一次回收会继续处理。中断的下载／解压活动 lease 在其所属进程退出后失效，下一次启动会回收相应临时目录。损坏 receipt、符号链接和无法安全检查的目录保留并输出诊断，避免递归删除未知文件。

## 边界和验证

包库与 lease 是多个应用进程之间的协作机制。普通 Node 插件仍具有当前用户的操作系统权限；这套回收机制不构成针对同用户恶意文件系统修改的沙箱。每轮有条目、层级、字节和退休数量预算；阻塞文件系统调用及平台极端故障的总退出时限验收仍在完整计划中。父应用异常退出、插件主线程卡死、实际使用摘要保留及同组子进程终止已有专用 macOS 故障证明，其他平台执行仍列在 `I2.supervision`。

`PluginPackageTests` 验证：更新候选／回滚历史保留、尚未提交的包保护、包库锁期间启停／卸载、活动下载暂存保护、失效进程与残留下载恢复、损坏索引／lease 保留、符号链接不跟随、未知目录保留、取消、分批回收及工作线程调度。跨进程测试实际启动 `PackageLeaseProbe`，并让进程不执行析构直接退出。

`PluginWebviewTests` 验证实际 Node 会话在安装索引引用被另一个所有者移除后仍可运行，退出后可回收；原生管理器卸载后安装目录消失、资源返回 Uninstalled；已有 100 次启停／重载压力测试继续作为正常管理操作与后台回收的回归检查。最新结果记录在 `CompletionAudit.json` 与 `evidence/ImplementationValidation.json`。
